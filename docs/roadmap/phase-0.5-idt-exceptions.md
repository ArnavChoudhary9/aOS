# Phase 0.5 — IDT and exception stubs

**Milestone:** M0 — It boots · **Depends on:** 0.4 · **Branch:** `phase/0.5-idt-exceptions`

## Goal

Every CPU exception (vectors 0–31) lands in a hand-written assembly stub, saves the full register state in one uniform trap frame, and reaches a Rust handler. For now that handler prints a readable dump and halts. This closes M0.

## Builds

- `kernel/src/arch/x86_64/idt.rs`: 256-entry IDT. Vectors 0–31 are interrupt gates (DPL0). #DF uses IST1, NMI uses IST2, #MC uses IST3. Load with `lidt`.
- `kernel/src/arch/x86_64/entry.S` (via `global_asm!`) or `#[unsafe(naked)]` functions: one stub per vector, generated by a macro. Vectors without a CPU error code push a dummy 0, then the vector number, then jump to a common stub that pushes all 15 GPRs, calls `trap_dispatch(&mut TrapFrame)`, restores, drops two words and runs `iretq`.
- `kernel/src/arch/x86_64/trap.rs`: `#[repr(C)] TrapFrame { r15..rax, vector, error_code, rip, cs, rflags, rsp, ss }`, with offsets asserted. Decodes #PF error bits (P/W/U/R/I) and reads CR2.
- Dump format: `EXCEPTION #PF (14) err=0x2 [not-present write kernel] cr2=0x…`, then the registers 4 per line, then a backtrace starting from the frame's rbp, then `qemu_exit(Failure)`.
- Test features: `test-pf` (writes to 0xdead0000) and `test-df` (unbounded recursion that overflows the boot stack, so #PF→#DF lands on IST1).
- `tests/gates/m0.toml` (the PF case) and `tests/gates/m0-df.toml`.

## Technical notes

- The interrupt ABI on stable Rust: no `extern "x86-interrupt"`. All entry is asm. The Rust side is a plain `extern "C" fn trap_dispatch(frame: *mut TrapFrame)`.
- Keep the stack 16-byte aligned before `call` in the common stub. After the CPU push (5 words) plus error code, vector and 15 GPRs, that is 22 words, so subtract 8 before the call.
- The common stub must test `cs & 3` and `swapgs` when coming from user mode. No user mode exists yet, but write it now and comment it.
- Vectors 32–255 get a 'spurious/unhandled' stub that logs the vector. Real IRQ wiring comes in 1.4.
- A #DF test needs a guard page under the boot stack, or the overflow silently corrupts memory. Until 1.2 adds paging, the agent may choose the Limine stack-size request plus a page unmapped through Limine's page tables. The simplest route is to defer `m0-df` into 1.2 if it isn't reliable now. Document the choice.

## Out of scope

- IRQ handling (1.4), user-mode faults as messages (2.7).

## Gate

`cargo xtask gate m0`: expects `EXCEPTION #PF \(14\)`, `cr2=0x0*dead0000`, `bt:` lines and a failure exit (the spec marks failure as expected). `m0-df` expects `EXCEPTION #DF` with `rsp` inside the IST1 range. Both pass, and so do the earlier gates.

## Manual checklist

- [ ] `cargo xtask gate m0` → PASS. Read the dump: is `err` decoded correctly as a not-present write from the kernel?
- [ ] `cargo xtask run --tcg` with feature `test-pf` → `target/qemu-int.log` shows `v=0e` and no triple fault (`cpu_reset`).
- [ ] Change the stub so it forgets to push the dummy error code for vector 3 (`int3`) and trigger `int3` → the dump is garbage. That shows why normalizing the frame matters. Revert.
