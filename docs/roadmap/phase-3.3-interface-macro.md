# Phase 3.3 — Interface macro and IPC runtime

**Milestone:** M3 — Core services · **Depends on:** 3.2 · **Branch:** `phase/3.3-interface-macro`

## Goal

Services stop hand-parsing bytes. An `#[interface]` attribute on a Rust trait generates a typed client stub and a server dispatch function, with `#[repr(C)]` argument structs, idempotency marks, capability parameters and a built-in version handshake.

## Builds

- `libs/aos-ipc-macros/` (proc-macro; `syn`, `quote`, `proc-macro2`): `#[interface(name = "echo", version = "1.0")] trait Echo { #[idempotent] fn echo(&self, x: u64) -> Result<u64, Error>; fn put(&self, data: &Bytes<256>) -> Result<(), Error>; fn take_cap(&self, c: Cap) -> Result<(), Error>; }`.
- It generates `EchoClient { ep: Slot, version: Negotiated }` with methods that pack args into a `#[repr(C)]` struct, call, and unpack the reply. It also generates `trait EchoServer` and `fn dispatch_echo(server, msg, reply) -> Handled`, plus per-method `IDEMPOTENT` consts for the retry logic in 4.3.
- `libs/aos-ipc/`: `Bytes<N>` (a `len: u16` plus `[u8; N]`, which must fit in 512), `Cap` param type (maps to send/recv cap slots), the `Message` view over regs+IpcBuffer, `serve(ep, &mut impl Dispatch)`, a loop running `reply_recv` that dispatches by `label.iface` and returns `BadArg` for unknown iface or method.
- Interface id = the first 16 bits of FNV-1a of the interface name, with collisions checked by xtask across all interfaces at build time. Method id = declaration order. Reordering methods is a major version bump (documented).
- Version handshake: every interface gets an implicit method 0, `connect(min_major, max_major) -> (major, minor)`. The client stub calls it lazily on first use and caches the result. A server provides a list of supported majors.
- Request ids: the client stub assigns an incrementing `req_id` per call (used by retry in 4.3).
- Host tests: macro expansion compiles for a sample interface; a mock transport round trip; every arg struct is ≤ 512 bytes (a compile-time assert generated by the macro); the version negotiation table.
- `services/echo` + `apps/echo-client` (test): replaces the hand-written ping-pong.

## Technical notes

- Only `#[repr(C)]`, `Copy` types without pointers are allowed as args (the macro checks via a marker trait `Wire`, implemented for ints, bools, fixed arrays, `Bytes<N>`, and structs with `#[derive(Wire)]`).
- Replies use the same encoding: MR0 = error code, then the return struct.
- Non-idempotent methods should return `MaybeDone` semantics in 4.3. Leave a hook now.

## Out of scope

- Retry and replay behaviour (4.3).
- IDL / C bindings (M7 uses hand-written C shims).

## Gate

`cargo xtask gate iface`: the echo client does 1000 calls through the generated stub, sends a 200-byte `Bytes`, transfers a cap, and negotiates version (client 1–2, server 1 → 1.0). Expect `echo-client: all ok v1.0`. Host macro tests run in `check`.
