# Phase 11.2 — Bundles and signing

**Milestone:** M11 — Updates · **Depends on:** 11.1 · **Branch:** `phase/11.2-bundles`

## Goal

Updates arrive as signed bundles. xtask builds and signs them on the host, and a new `updsrv` service verifies the signature and every file hash before accepting anything.

## Builds

- Bundle format: a ustar containing `bundle.bin` (an `aos-manifest`-style binary listing files `{path, sha256, size}`, plus the services' manifests) and `bundle.sig` (ed25519 over `bundle.bin`), plus the files.
- `xtask bundle --services fat32,vfs --out target/bundle-x.tar`: builds those services (optionally with a version bump from a profile), writes `bundle.bin`, and signs with `keys/dev-ed25519.key` (generated by `xtask keygen`; the private key is gitignored and the public key committed at `keys/dev-ed25519.pub`).
- `services/updsrv`: public key embedded at build time (`include_bytes!`); `Update` interface `install(path)` → verify the signature (`ed25519-compact`) and each file's sha256 (`sha2`), then run the planner dependency check against installed + incoming. It rejects with a reason. Install itself comes in 11.3.
- Incoming location: `/system/update/incoming/` (copied in with mtools, or later downloaded).

## Technical notes

- Never parse unsigned content beyond what's needed to check the signature.
- Key rotation is out of scope; document it as a risk.

## Out of scope

- Writing files (11.3).

## Gate

`cargo xtask gate bundle`: a valid bundle → `updsrv: bundle ok (2 services)`; a bundle with one flipped byte in an ELF → `updsrv: rejected: hash mismatch fat32.elf`; a bad signature → `rejected: signature`; an unsatisfiable requirement → `rejected: vfs requires fs >=9`. Earlier gates pass.

## Manual checklist

- [ ] `xtask bundle` twice gives identical bundle.bin (reproducible), given the same inputs.
